# Software Requirements Specification (SRS) - SorokChat Messenger (Frontend)

> Цей документ описує цільовий стан frontend-системи (target design), а не поточний стан реалізації в src. Поточна реалізація може відрізнятися від описаного стану до досягнення MVP.

**Тип інформаційного елемента за ISO/IEC/IEEE 15289:2019:** Specification
**Стандарт:** ISO/IEC/IEEE 29148:2018

> Цей документ описує лише frontend-частину застосунку. Взаємодія з API Gateway є зовнішнім інтерфейсом, а не внутрішньою логікою backend-системи.

## 1. Призначення ПЗ

Frontend-застосунок SorokChat Messenger — веб-клієнт для безпечної
комунікації з E2E-шифруванням, побудований на Angular із застосуванням
методології Feature-Sliced Design (FSD). Він взаємодіє з API Gateway
через зовнішній інтерфейс, але не описує серверну реалізацію.

## 3. Вимоги до продуктивності ПЗ

- Initial bundle: ≤ 500 KB (gzipped).
- Time to Interactive (TTI): ≤ 3 с на 4G.
- Lazy loading модулів FSD-шарів: `features`, `pages`.

## 4. Вимоги до зовнішніх інтерфейсів

- **Сфера опису:** лише frontend-частина застосунку.
- **Інтеграція з зовнішньою системою:** взаємодія з backend-сервісами розглядається лише як зовнішній інтерфейс, а не як частина цього документа.
- **Сховище браузера:** IndexedDB для токенів, ключів шифрування, локального кешу повідомлень та стану офлайн-черги.
- **Crypto:** власні frontend-пакети-обгортки над WebCrypto API; використовується **AES-256-CBC** для шифрування вмісту та **HMAC-SHA-256** для перевірки цілісності.

## 5. Вимоги до даних

- **Повідомлення (локально):** id, chatId, ciphertext, mac, timestamp, status.
- **Черга офлайн:** список невідправлених повідомлень з retry-логікою.
- **Стан сесії:** refresh token зберігається в `HttpOnly` secure cookie; локальні ключі шифрування та токени доступу зберігаються в IndexedDB; дані у браузері не дублюються у localStorage як основне сховище.

## 6. Архітектурні вимоги (FSD)

Структура `src/`:

```text
src/
├── app/                 # Ініціалізація, провайдери, роутинг
├── pages/               # Сторінки (Chat, Login, Register)
├── widgets/             # Складені блоки (ChatList, MessageThread)
├── features/            # Фічі (send-message, rotate-key, auth)
├── entities/            # Бізнес-сутності (user, chat, message)
├── shared/
│   ├── ui/              # Базові UI-компоненти
│   ├── config/          # Конфігурація та константи
│   ├── utils/           # Загальні утиліти
│   ├── api/             # HTTP/WS адаптери
│   ├── styles/          # Глобальні стилі, токени, теми
│   └── assets/          # Статичні ресурси для UI-слою (іконки, шрифти, картинки)
├── index.ts             # Точка входу застосунку
└── main.ts              # Ініціалізація кореневого bootstrap
```

Правила FSD:
- Залежності лише зверху вниз (`shared → entities → features → widgets → pages → app`).
- Публічний API кожного слайсу через `index.ts`.
- API Gateway є зовнішнім сервісом і не є частиною внутрішньої структури FSD.

## 7. Вимоги до безпеки ПЗ

- Токени та ключі шифрування зберігаються виключно в **IndexedDB** в межах браузерного середовища.
- Приватні ключі не залишають браузер і не дублюються у localStorage/sessionStorage як основне сховище.
- Усі криптооперації виконуються у власних frontend-пакетах-обгортках над **WebCrypto API**.
- У frontend використовується **AES-256-CBC** для шифрування вмісту та **HMAC-SHA-256** для перевірки цілісності.
- Заборона `eval()`, `innerHTML` без санітизації.
- Усі зовнішні виклики відбуваються лише як зовнішній інтеграційний інтерфейс; серверна логіка не є частиною цього документу.

## 8. Критерії верифікації

- Unit-тести: фреймворк для модульних тестів у frontend-проєкті.
- E2E: end-to-end перевірка основних користувацьких сценаріїв.
- Static analysis: ESLint + TypeScript strict mode.
- Integration-тести: перевірка взаємодії frontend ↔ API Gateway.
