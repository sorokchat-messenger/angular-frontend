# Business Requirements Specification (BRS) - SorokChat Messenger

**Тип за ISO 15289:2019:** Specification

**Стандарт:** ISO/IEC/IEEE 29148:2018

## 1. Бізнес-проблема

Існуючі месенджери (Telegram, Viber, WhatsApp) зберігають метадані
та вміст повідомлень на серверах компаній, часто розташованих за межами
України. Користувачі не мають контролю над своїми ключами шифрування
та не можуть гарантувати конфіденційність.

## 2. Бізнес-можливість

Створити український месенджер з **end-to-end шифруванням**,
**контрольованим управлінням ключами** та **прозорим журналом аудиту**,
що відповідає вимогам приватності.

## 3. Бізнес-цілі

| ID | Ціль | Метрика успіху |
|----|------|----------------|
| BG-1 | Забезпечити конфіденційність повідомлень | 100% повідомлень E2E-зашифровані |
| BG-2 | Забезпечити цілісність повідомлень | 100% повідомлень з валідним MAC |
| BG-3 | Забезпечити контроль користувача над ключами | Ротація ключа доступна кожному адміну чату |
| BG-4 | Забезпечити роботу офлайн | Користувач може читати кеш без мережі |
| BG-5 | Масштабованість | Підтримка чатів до 1000 учасників |

## 4. Обсяг (Scope)

**У скоупі:**
- Веб-клієнт (Angular + FSD).
- Реєстрація, автентифікація, авторизація.
- Створення та адміністрування чатів.
- Управління ключами шифрування та цифровими підписами.
- Офлайн-режим.

**Поза скоупом (на цьому етапі):**
- Мобільні застосунки (у майбутньому).
- Десктопні застосунки (у майбутньому).
- Дзвінки та відеозв'язок.

## 5. Обмеження

- Веб-клієнт - основний продукт на цьому етапі.
- Стек frontend: Angular + Feature-Sliced Design.
- Один чат - до 1000 учасників.

## 6. Припущення

- Користувачі мають сучасний браузер.
- Користувачі готові зберігати власні ключі (або покладатися на
  безпечне локальне сховище).
