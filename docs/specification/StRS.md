# Stakeholder Requirements Specification (StRS) - SorokChat Messenger

**Тип за ISO 15289:2019:** Specification

**Стандарт:** ISO/IEC/IEEE 29148:2018

## 1. Зацікавлені сторони

| Стейкхолдер | Роль | Ключові потреби |
|-------------|------|-----------------|
| Користувач-українець | Кінцевий користувач | Конфіденційність, простота, українська мова UI |
| Користувач, що цінує приватність | Кінцевий користувач | E2E-шифрування, контроль ключів |
| Адміністратор чату | Користувач з правами | Керування учасниками та ключами |
| Security-експерт | Аудитор | Прозорість, журнал аудиту, відповідність |
| Розробник frontend | Інженер | Чіткі вимоги, FSD-структура, тестованість |
| Власник продукту | Замовник | Метрики успіху, бізнес-цілі |

## 2. Вимоги зацікавлених сторін

### StR-01: Приватність
> Як користувач, я хочу, щоб мої повідомлення були зашифровані так,
> щоб навіть сервер не міг їх прочитати, щоб моє листування залишалося
> приватним.

**Критерій прийнятності:** 100% повідомлень у чаті передаються у
зашифрованому вигляді; сервер не має доступу до відкритого тексту.

### StR-02: Контроль ключів
> Як адміністратор чату, я хочу мати можливість змінювати ключ
> шифрування чату, щоб обмежити доступ колишніх учасників.

**Критерій прийнятності:** ротація ключа виконується за ≤ 5 секунд,
усі учасники отримують новий ключ, подія логується.

### StR-03: Цілісність
> Як користувач, я хочу бути впевненим, що повідомлення не було
> змінено по дорозі, щоб довіряти переписці.

**Критерій прийнятності:** кожне повідомлення містить MAC;
при невідповідності - UI показує попередження.

### StR-04: Простота
> Як користувач, я хочу інтуїтивний інтерфейс українською мовою,
> щоб швидко почати користуватися.

**Критерій прийнятності:** новий користувач може надіслати перше
повідомлення за ≤ 2 хвилини без інструкцій.

### StR-05: Офлайн-режим
> Як користувач, я хочу мати доступ до історії чатів без інтернету.

**Критерій прийнятності:** при втраті з'єднання UI показує кешовані
повідомлення; нові - ставляться в чергу.

### StR-06: Цифрові підписи
> Як адміністратор, я хочу підписувати критичні дії (ротація ключа),
> щоб мати доказ авторства.

**Критерій прийнятності:** кожна дія адміністратора супроводжується
цифровим підписом, який можна верифікувати.

## 3. Пріоритети

| ID | Пріоритет | Обґрунтування |
|----|-----------|---------------|
| StR-01 | Critical | Основна цінність продукту |
| StR-02 | High | Відрізняє від конкурентів |
| StR-03 | High | Базова вимога безпеки |
| StR-06 | Medium | Важливо для адмінів |
| StR-04 | Medium | Впливає на retention |
| StR-05 | Medium | Покращує UX |
