# Sorokchat Messenger — технічна специфікація

**Версія**: **1.0.0**

**Автор**: **Сороковський Андрій**

Цей документ описує технічні вимоги та основні складові проєкту Sorokchat Messenger. Проєкт призначений для забезпечення безпечного обміну повідомленнями, роботи з чатами, авторизації користувачів та управління правами доступу.

## 1. Ціль системи
Створити веб-месенджер, який підтримує реальний час, безпечне зберігання даних, контроль доступу до функцій і просту масштабованість.

## 2. Основні функціональні вимоги
- реєстрація користувача;
- авторизація та вихід з облікового запису;
- створення та керування чатами;
- надсилання та отримання повідомлень;
- збереження історії переписки;
- контроль ролей і доступу до функцій.

## 3. Нефункціональні вимоги
- безпечне зберігання чутливих даних;
- підтримка HTTPS та захищених WebSocket-з’єднань;
- локальне шифрування чутливих даних;
- серверна перевірка ролей і підписки.

## 4. Взаємодія клієнта з бекендом
Клієнт взаємодіє з бекендом через REST API та захищені підключення у реальному часі.

Для REST-запитів використовується Angular `HttpClient`. Базовий URL REST API визначається змінною середовища `API_URL`; якщо вона не задана, застосовується префікс `/api`. REST API використовує HTTPS і застосовується для HTTP-операцій керування даними та сесією: реєстрації, авторизації, оновлення й анулювання токенів, отримання профілю, а також створення, отримання й видалення чатів.

Для оновлення повідомлень у реальному часі передбачено WebSocket-підключення через захищений протокол `wss://`. Поточна реалізація зберігає повідомлення локально та не містить WebSocket-клієнта.

Ендпоінти організовані у сегментах `api/` сутностей і фіч відповідно до архітектурної структури проєкту. Контракти ендпоінтів імпортуються з пакета `@sorokchat-messenger/contracts`. У поточній документації окремого OpenAPI/Swagger-опису API немає.
