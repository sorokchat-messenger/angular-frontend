# Verification Plan - SorokChat Messenger

**Тип за ISO 15289:2019:** Plan

**Версія:** 1.0

## 1. Мета

Визначити підхід до верифікації та валідації вимог SyRS/SRS
відповідно до ISO/IEC/IEEE 29148:2018.

## 2. Обсяг верифікації

- Усі функціональні вимоги (FR-01…FR-10).
- Усі нефункціональні вимоги (NFR-01…NFR-06).
- Критичні архітектурні рішення (ADR-02, ADR-03, ADR-05).

## 3. Рівні тестування

| Рівень | Інструмент | Покриття | Відповідальний |
|--------|------------|----------|----------------|
| Unit | vitest / Jasmine | ≥ 70% | Розробник |
| Integration | vitest + Testing Library | Ключові сервіси | Розробник |
| E2E | Playwright / Cypress | Критичні сценарії | QA |
| Security | OWASP ZAP, ручний аудит | Крипто, автентифікація | Security |
| Performance | Lighthouse, k6 | NFR-01, NFR-02 | QA + DevOps |
| Accessibility | axe-core | WCAG 2.1 AA | QA |

## 4. Матриця верифікації

| Вимога | Метод | Інструмент | Критерій проходження |
|--------|-------|------------|----------------------|
| FR-01 | T | vitest + Playwright | Реєстрація проходить, помилки валідації коректні |
| FR-02 | T | vitest + Playwright | Після відповіді API Gateway стан авторизації оновлюється за ≤ 500 мс |
| FR-03 | T | Playwright | Доступ без прав — 403 у UI/після відповіді API Gateway |
| FR-04 | T | vitest | Чат створено, UI оновлено, метадані відображаються коректно |
| FR-05 | T + D | Playwright | Усі дії адміна працюють у frontend-інтерфейсі |
| FR-06 | T + A | vitest + крипто-аналіз | Ротація ключа відображається в UI ≤ 5 с, результат валідний |
| FR-07 | T + A | vitest + WebCrypto | Підпис перевіряється у браузері |
| FR-08 | T | vitest + Playwright | Повідомлення шифрується, MAC перевіряється, статус доставки відображається |
| FR-09 | D | Ручний + Playwright | Офлайн-черга працює у frontend |
| FR-10 | I + T | Рев'ю + vitest | Критичні події відображаються у журналі аудиту |
| NFR-01 | T | Lighthouse + k6 | TTI ≤ 3 с, 1000 клієнтів OK |
| NFR-02 | A + T | k6 | UI/стан чату тримається для 1000 учасників |
| NFR-03 | A + I | OWASP ZAP + рев'ю | Немає Critical/High вразливостей у frontend-інтеграції |
| NFR-04 | A | Моніторинг | Uptime ≥ 99.5% (30 днів) |
| NFR-05 | D | Ручний | UI зрозумілий 5 тестувачам |
| NFR-06 | A | coverage report | ≥ 70% покриття |

**Методи:** A - аналіз, D - демонстрація, I - інспекція, T - тест.

## 5. Середовища

|------------|-------------|-----|
| Local | Розробка, unit | localhost |

## 6. Критерії приймання релізу (DoD)

- ✅ Усі Critical / High вимоги верифіковано.
- ✅ Покриття unit-тестами ≥ 70%.
- ✅ Security-аудит без Critical/High.
- ✅ Performance: TTI ≤ 3 с на 4G.
- ✅ Усі дефекти Severity Critical/High - закрито.
- ✅ Traceability Report оновлено.

## 7. Розклад

| Фаза | Коли | Тривалість |
|------|------|-----------|
| Unit + Integration | Під час розробки | Постійно |
| E2E | Перед кожним PR | 5 хв |
| Security | Перед релізом | 1 день |
| Performance | Перед релізом | 4 год |
| UAT | За 3 дні до релізу | 2 дні |

## 8. Ризики

| Ризик | Ймовірність | Вплив | Мітигація |
|-------|-------------|-------|-----------|
| WebCrypto не підтримується в старому браузері | Low | High | Поліфіл + fallback |
| Нестабільні E2E через WebSocket | Medium | Medium | Retry-логіка в тестах |
| Проблеми з Safari iOS офлайн | High | Medium | Окреме тестування |
