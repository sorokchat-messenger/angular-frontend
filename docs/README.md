# Документація проєкту Sorokchat Messenger

> Цей документ описує цільовий стан системи (target design), а не поточний стан реалізації в коді. Поточна реалізація в src може відрізнятися від описаного стану до досягнення MVP.

## Обсяг і межі документації

Ця документація описує лише frontend-обсяг проєкту Sorokchat Messenger: веб-клієнт, UX, маршрутизацію, взаємодію користувача з чатами, безпеку на клієнтському боці, локальний кеш та офлайн-режим. Документи не описують серверну систему, структуру даних, базу даних, API Gateway, аутентифікацію на backend-стороні або інфраструктурні сервіси як частину цього scope.

**Не включено в цей scope:**
- backend-реалізація та доменні сервіси серверної частини
- схема даних, база даних та їхнє зберігання
- розгортання, DevOps-конфігурація та інфраструктурні компоненти
- логіка взаємодії з зовнішніми службами, якщо вона не є клієнтською інтеграцією

Структура документації відповідає стандарту **ISO/IEC/IEEE 15289:2019** (7 типів інформаційних елементів життєвого циклу).

| Папка | Тип інформаційного елемента за ISO/IEC/IEEE 15289:2019 | Зміст |
|-------|-----------------------------------------------------------|-------|
| `description/` | Description | Операційна концепція, архітектурний опис, точки зору та подання |
| `specification/` | Specification | Бізнес-, системні та software requirements |
| `plan/` | Plan | Плани управління вимогами та верифікації |
| `policy/` | Policy | Політика проєкту та правила архітектури |
| `procedure/` | Procedure | Процедури життєвого циклу вимог |
| `report/` | Report | Звіти про трасування та верифікацію |
| `request/` | Request | Шаблони запитів на зміну |

Ця документація використовує **ISO/IEC/IEEE 15289:2019** для класифікації типів інформаційних елементів життєвого циклу, **ISO/IEC/IEEE 29148:2018** для структури та якості вимог, та **ISO/IEC/IEEE 42010:2022** для опису архітектури.
