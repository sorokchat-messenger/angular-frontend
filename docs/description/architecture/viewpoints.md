# Architecture Viewpoints - SorokChat Messenger

**Тип за ISO 15289:2019:** Description

**Стандарт:** ISO/IEC/IEEE 42010:2022

Точка зору (Viewpoint) - це шаблон, який визначає, як будувати подання
(View) для конкретної групи зацікавлених сторін. Кожна точка зору
охоплює певні проблеми (Concerns) і використовує визначені моделі.

---

## VP-01: Функціональна точка зору (Functional Viewpoint)

| Поле | Значення |
|------|----------|
| **ID** | VP-01 |
| **Назва** | Functional Viewpoint |
| **Проблеми (Concerns)** | Сценарії використання, розподіл функцій між модулями, взаємодія користувача з системою |
| **Стейкхолдери** | Frontend-розробники, Product Manager, QA |
| **Моделі** | UML Component Diagram, Use Case Diagram, FSD-структура шарів |
| **Мова/нотація** | UML 2.5 + Mermaid |
| **Джерело** | ISO/IEC/IEEE 42010:2022, Annex A |

**Правила побудови:**
1. Кожен компонент має бути віднесений до шару FSD (`shared`, `entities`, `features`, `widgets`, `pages`, `app`).
2. Кожен Use Case - пов'язаний із функціональною вимогою (FR-xx).
3. Залежності між компонентами - лише «зверху вниз» (правило FSD).

## VP-02: Безпекова точка зору (Security Viewpoint)

| Поле | Значення |
|------|----------|
| **ID** | VP-02 |
| **Назва** | Security Viewpoint |
| **Проблеми** | Шифрування, управління ключами, MAC, цифрові підписи, захист сесій |
| **Стейкхолдери** | Security-експерт, адміністратор чату, користувач |
| **Моделі** | Data Flow Diagram (DFD), Threat Model (STRIDE), State Diagram для ключів |
| **Мова/нотація** | STRIDE, DFD (Yourdon/DeMarco) |
| **Джерело** | ISO/IEC/IEEE 42010:2022 + OWASP Threat Modeling |

**Правила побудови:**
1. Кожен потік даних із чутливими даними має бути позначений шифруванням у відповідності до вимоги проєкту: **AES-256-CBC**.
2. Для кожної загрози STRIDE - визначено контрзахід.
3. Кожен ключ має життєвий цикл: генерація → розповсюдження → використання → ротація → відкликання.
4. Токени та ключі зберігаються виключно в **IndexedDB** у межах фронтенд-складу.

## VP-03: Інформаційна точка зору (Information Viewpoint)

| Поле | Значення |
|------|----------|
| **ID** | VP-03 |
| **Назва** | Information Viewpoint |
| **Проблеми** | Структура даних, зберігання, кешування, офлайн-черга у браузері |
| **Стейкхолдери** | Frontend-розробники, QA, Product Manager |
| **Моделі** | ER-діаграма, State Diagram повідомлення, схема IndexedDB |
| **Мова/нотація** | Crow's Foot Notation, UML State Machine |
| **Джерело** | ISO/IEC/IEEE 42010:2022 |

**Правила побудови:**
1. Кожна сутність має власний слайс у FSD-шарі `entities`.
2. Кожне поле має тип і політику зберігання (persistent / session / memory).
3. Для кожного стану повідомлення — визначено перехід та тригер.

## VP-04: Точка зору розгортання (Deployment Viewpoint)

| Поле | Значення |
|------|----------|
| **ID** | VP-04 |
| **Назва** | Deployment Viewpoint |
| **Проблеми** | Хостинг, WebSocket-з'єднання, HTTPS, CDN |
| **Стейкхолдери** | DevOps, SRE, Frontend-розробники |
| **Моделі** | UML Deployment Diagram, мережева топологія |
| **Мова/нотація** | UML 2.5 Deployment |
| **Джерело** | ISO/IEC/IEEE 42010:2022 |

**Правила побудови:**
1. Усі зовнішні комунікації - виключно HTTPS/WSS (TLS 1.3) між frontend і API Gateway.
2. SPA-бандл роздається через CDN.
3. WebSocket-з'єднання з API Gateway розглядається як зовнішня інтеграція, а не як внутрішній вузол frontend-архітектури.
